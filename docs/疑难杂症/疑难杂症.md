## 网络

### 为什么 Ping 地址 A，却收到节点 B 的不可达回复？

:::info
在日常网络运维中，我们经常会遇到一种看似诡异的现象：明明发起 Ping 测试的目标是服务器 A，终端弹出的却是来自另一个 IP（节点 B）的报错信息。
ICMP 报文并没有按预期达到目标 A，也没有表现为常见的“请求超时（Request timed out）”，而是被链路上的某台设备（节点 B）以显式的错误信息直接退回。
:::

在 IP 网络的逐跳（Hop-by-Hop）转发机制中，路由器或三层交换机会根据数据包的目的 IP 地址查找本地路由表。

当终端向地址 A 发送 ICMP Echo Request 数据包时，数据包在网络中正常流转，到达了链路上的中间节点 B（通常是源主机的默认网关，或是链路上的某台核心/汇聚路由器）。此时，节点 B 遇到了“无法继续转发”的障碍，常见原因包括：

- 路由缺失：节点 B 的路由表中没有去往目标 A 所在网段的明细路由，同时也没有配置默认路由（缺省路由）。

- 安全策略拦截：去往目标 A 的出接口配置了严格的 ACL（访问控制列表）或防火墙安全策略，流量被显式阻断（D rop）。

- 黑洞路由：为了防止路由环路或抵御攻击，节点 B 上配置了指向 A 网段的 Null0 黑洞路由。

## 系统
### 台式机无法进入Ubuntu live
1、使用`rufus`或者`Win32DiskImager`制作`Ubuntu`启动盘；

2、开机选择U盘启动；

3、启动菜单跳到`try or install`按`e`;

4、找到`linux`那一行，再结尾添加`nomodeset`；

5、按`ctrl`+`x`启动

## 桌面
### 恢复win32 disk imager刻录过的U盘

1、按`win`+`R`在运行框`diskpart`

2、在命令行输入`list disk`列出所有硬盘

3、输入`select disk 1`，可根据容量判断是1还是？

4、输入`clean`，清除磁盘；

5、输入`create partition primary`，创建分区；

6、输入`active`，激活分区；

7、输入`format fs=ntfs quick`，以ntfs格式化硬盘；

8、分配盘符`assign letter=H`。
